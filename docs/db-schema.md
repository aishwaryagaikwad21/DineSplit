# DineSplit Database Schema

## 1. Restaurant

### Fields
- _id
    - Data type: ObjectID
    - Required: true
    - unique: true
    - Default: Auto-generated by MongoDB
- name
    - type: String
    - required: true
    - Unique: false
    - validation: non-empty string
- address
    - type: String
    - required: true
    - validation: non-empty string
- email
    - type: String
    - required: true
    - unique: true
    - validation: npm validator
- password
    - type: String
    - Required: true
    - Unique: false
    - validation: strong password
- socialMediaHandles
    - type: Map, 
    - of: String
    - Required: false
- token
    - type: String
    - unique: true
    - Reference/File: Token used for restaurant authentication

## 2. Menu
### Fields
- id
    - type: ObjectID
    - Required: true
    - unique: true
    - Default: Auto-generated by MongoDB
- restaurant_id
    - type: ObjectID
    - Required: true
    - validation: valid ObjectID
    - Reference/File: References Restaurant (FK)
- menu
    - type: File (Json)
    - Required: true
    - validation: valid json file
    - Description: use npm multer to receive json file

## 3. Order

### Fields

- order_id
    - Data type: ObjectID
    - Required: true
    - unique: true
    - Default: Auto-generated by MongoDB
    - Reference/File: Primary identifier
- restaurant_id
    - type: ObjectID
    - Required: true
    - validation: valid ObjectID
    - Reference/File: References Restaurant (FK)
- table_number
    - type: Number
    - required: true
    - validation: positive integer
- items
    - type: Array of objects [{ }]
    - required: true
    - validation: must contain at least 1 item
    - Reference/File: Refers to Menu file / embedded data
    - Description: Stores the dish name, price at the time
      of ordering, and quantity
- status
    - type: String
    - enum: ["active", "inactive"]
    - required: true
    - default: "active"
    - Description: whether the order is active or inactive - waiter can add items as and when ordered - inactive means ready to generate final bill. 

### items[{ }]
- dish_name
    - type: String
    - required: true
    - validation: non-empty string
- price
    - type: Number
    - required: true
    - validation: must be greater than 0
- quantity
    - type: Number
    - required: true
    - Validation: Positive integer

## 4. Bill
### Fields
- bill_id
    - type: ObjectID
    - required: true
    - unique: true
    - validation: valid bill format
    - Reference/File: Primary identifier
- order_id
    - type: ObjectID
    - Required: true
    - Unique: true
    - Validation: valid order reference
    - Reference/File: References Order
- total_amount
    - type: Number
    - required: true
    - Unique: false
    - Validation: valid positive number
    - Reference/File: References Order items
- status
    - type: Boolean
    - required: true
    - validation: enum ["unpaid", "paid"]
    - default: "unpaid"
- createdAt
    - type: Date
    - required: true

## 5. Split Bill
- group_id
    - type: ObjectID
    - required: true
    - unique: true
    - Reference: primary identifier
- bill_id
    - type: ObjectID
    - required: true
    - unique: true
    - reference/file: references bill
- split_type
    - type: String
    - validation: enum ["equal", "item-wise"]
- separate_bill
    - Type: Array of objects
    - required: true
    - validation: must contain at least 2 members
    - reference/ File: embedded data

### separate_bill[ ]
- member_name
    - Type: String
    - Required: true
    - Validation: non-empty string
- amount_to_pay
    - type: Number
    - required: true
